# The 88 notes

Each piano note (MIDI 21 to 108) is bound to one painted shape (`mapping.json`, bindings `note-<n>` with a `part`).
Holding a note plays its shape's animation from frame 0, the painting as drawn, to frame 1 at a steady pace over
4 seconds (the binding's `hold`), so how long the note is held is how far the animation gets. Letting go plays it back
in about 0.3 s (the binding's `release`). Low notes sit on the bigger shapes and high notes on the tiny ones.

## How they were made

The notes follow the object pattern (`docs/object-animation-pattern.md`), with Matt's taste from section 5a, run as a
batch:

1. `uv run scripts/note_kit.py sheet` draws every note shape in context (`contact-*.jpg` here).
2. The notes were split into 15 batches of neighbouring shapes. For each batch, a builder looked closely at its
   shapes and offered three ideas per note: an own-nature morph, a character action, and a celebration or pun
   (`docs/objects/note-<n>/ideas.md`).
3. One idea per note was picked centrally across the whole keyboard, so the 88 stay varied: no idea used twice, none
   borrowed from the parameter objects, and only a minority built on an eye opening.
4. Each batch was built in one script, `scripts/notes_b01.py` to `notes_b15.py`, on the shared kit
   `scripts/note_kit.py`. `uv run scripts/notes_<batch>.py` draws each note at 0, 0.2, 1, 2, 3 and 4 s held
   (`strip.png`); `export` writes `build.json`.
5. The builds were merged into `mapping.json`, and `node scripts/note_frames.mjs` rendered every note from the app in
   one page load (`app-strip.png` in each note's folder). `node scripts/note_frames.mjs --timing` checks the hold pace.

Rules particular to notes: something must show within a 0.2 s tap, something new should arrive about every second,
and the payoff comes at 4 s. Big low notes may build big and slow; tiny high notes stay small, bright and quick. Each
drawing stays near its own shape so chords don't bury the neighbours. Each note has at most about 30 sprites.

A note whose shape vanishes into what it draws (57, 60, 87) sets `"own": false` on its `around` sprites, so the
faded shape no longer stays masked in front of them; only its `front` shapes do.

Note 72 used to sit on the mushroom stem's drop (f285), which the upper 8' drawbar hides; it moved to the
purple pod beside it (f284).
